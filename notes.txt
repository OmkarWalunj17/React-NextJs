Why do frontend frameworks exist ?
------------------------------------------------------------------------------------------
1) Keeping a UI in sync with Data is really hard and a lot of work -> React, Angular.
2) They enforce a correct way of structuring and writing code.
3) They give developers and teams a consistent way of building front end applications.

===========================================================================================

What is React ?
-------------------------------------------------------------------------------------------
1) JS library for building UIs.
2) declarative, component based, state driven.
3) declarative syntax called JSX is used to describe how components look like.
4) decalrative : telling React what a component should look like, based on current data/state.
5) React is abstraction away from DOM: we never touch DOM.
6) JSX: a syntax that combinesHTML, CSS, JS, as well as referring other components.

7) React reacts to state changes by re-rendering the UI.
8) React is just a library.
9) Reason: It is just the view layer. We need to pick multiple libraries to build a complete application.
10) Complete frameworks built on top of React - NextJs, Remix.

-----------------------------------------------------------------------------------------------

Summary :
1) Rendering components on a webpage UI based on their current state.
2) Keeping the UI in sync with state, by re-rendering (reacting) when state changes.

What are the two options to setup a React Project ?

1) Create React App
2) Vite  

=========================================================================================

Create React App :
1) Already configured with ESLint, Prettier, Jest and Babel.
2) Uses slow and outdated technologies under the hood like webpack.
3) Never use for a real world app, must be used only for tutorials and experiments.

Under the Hood:
1) CRA - sets up the React project.
2) Webpack - bundling/building/
3) Babel - transpiles modern Javascript/JSX.
4) ESlint - linting.
5) Jest - testing.

Drawbacks:
1) slow and outdated.
2) not used for modern world app.

=========================================================================================

Vite :
1) Modern build tool 
2) Also contains starter templates
3) Manual setup of ESlint, Prettier and Jest.
4) Used for modern world apps.
5) Extremely Fast Hot Module Replacement (HMR).

Chapter 1: Components, Props, JSX
----------------------------------------------------------------------------------------------
React.StrictMode:
The only thing it does is that during development it will render all components twice in order to find certain bugs.

And also React will check if we're using outdated parts of the React API.

===============================================================================================

Components : 
1) React applications are entirely made out of components.
2) Building blocks of user interfaces in React. 
3) React takes all components and draws them on a webpage/UI.
4) Technically, React renders a view for each component.
5) And all these views together make up the UI.
6) Component can also be called a piece of UI that has its own data, JS logic, 
   and appearance how it works and looks.
7) We build complex UIs by building multiple components and combining them.
8) Components can be reused, nested inside each other, and pass data between them.
9) Component Tree can be used to identify the component hierarchy.
10) We write new components using functions.

-----------------------------------------------------------------------------------------------

JSX :
1) Declarative syntax to describe what components look like and how they work.
2) Components must return a block of JSX.
3) Extension of Javascript that allows us to embed JS, CSS and React components into HTML.
4) Babel : JSX to JS
5) Each JSX element is converted to a React.createElement function call.
6) We could use React without JSX.
    i) makes code hard to understand and read.


JSX is decalrative ?
------------------------------------------------------------------------------------------------
Imperative: JS (How to do things ?)
1) Manual DOM element selections and DOM traversing.
2) Step-by-step DOM mutations until we reach the desired UI.

Declarative: React (What we want)
1) Describe what UI should look like using JSX, based on current data.
2) React is an abstraction away from DOM: we never touch the DOM.
3) Instead, we think of the UI as a reflection of the current data.
------------------------------------------------------------------------------------------------
